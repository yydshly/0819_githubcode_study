02 / Mechanism

确定性，不等于简单随机

关键不是“随机画一个头像”，而是把每个视觉轴变成可寻址、可冻结、可约束的变量。

  1. 01规范化

    NFC、trim、lowercase，让人类认为相同的名称保持一致。

    " Alain " → "alain"
  2. 0232-bit 混合

    字符串只哈希一次，字符微小变化触发视觉雪崩。

    seedState(name)
  3. 03命名 Trait

    形状、色相、眼距分别用自己的 key 派生，新增特征不扰动旧头像。

    stream(state, "eye.gap")
  4. 04约束几何

    比例、间距和 face region 共同保证身体在画框内、眼睛尽量在脸内。

    [0,1) → safe range
  5. 05可访问配色

    OKLCh 设计后落到 sRGB，并自动调整眼睛明暗以满足默认对比度。

    contrast ≥ 4.5:1
  6. 06SVG 序列化

    没有模型推理、数据库或图片文件；URL 和 seed 就能重建身份。

    pure function → SVG
最值得复用的设计

hash(seed, traitKey) 让程序化系统可以增加新维度而不重排已有结果。这个模式能迁移到游戏角色、地图、声音、测试夹具和数据可视化。

03 / Product Scenarios

它解决的是“先有身份”，不是“还原长相”

在用户上传照片之前、Agent 还没有品牌资产时，用零存储成本提供可辨识的默认身份。

01

社区与协作产品

评论区、成员列表、协作光标和新用户默认头像。无需上传、裁切或内容审核。

  • 适合：高密度列表
  • 价值：即时可辨识
02

多 Agent 工作台

用稳定外观区分研究、检索、写作和执行 Agent；表情可映射运行状态。

  • 适合：角色归因
  • 价值：状态可视化
03

仓库与团队标识

为代码仓库、项目、频道或临时小组生成统一、可缓存的视觉占位符。

  • 适合：非人物实体
  • 价值：无资产启动

固定 seed 天然适合截图测试、Storybook、Mock 数据和回归夹具。

04 / Extension Map

从头像组件，扩展为产品身份协议

以下是本研究建议，不是上游已经实现的能力。优先级从产品验证到研究实验逐层推进。

P1 · 产品层

Agent 状态适配器

把 idle / thinking / working / success / error 映射到表情、动效和语义标签；保持状态信息不只依赖颜色。

最先验证
P2 · 品牌层

可版本化主题令牌

把 shape 白名单、色相区间、背景和动画规则封装成品牌 preset，并记录生成 generation。

复用价值高
P3 · 平台层

多语言渲染与缓存

增加服务端、WASM 或多语言实现的 parity fixture；用 HMAC 用户 ID 避免泄露邮箱和跨站追踪。

生产化关键
P4 · 研究层

感知辨识评测

测量 50 / 500 / 5000 头像下的辨识、记忆和误认率，并比较 Blobatar、Identicon、首字母和 DiceBear。

论文方向
P5 · 图形层

可插拔形状语法

探索保持 containment 和版本稳定性的 shape plugin 接口；新增形状必须显式进入新 generation。

算法工程
P6 · 无障碍

非视觉身份通道

为头像生成稳定的文本描述、触觉/声音提示和色觉缺陷友好模式，避免把身份只编码在色相中。

HCI 课题

05 / Research Boundary

研究判断

Blobatar 的算法新颖性有限，但它是研究“程序化身份如何进入真实产品”的优秀、可读、可运行基线。

产品 / HCI高
工程架构高
基础算法低
实验基线中高

0132-bit 状态不是安全哈希数万级身份后要认真评估严格碰撞和感知碰撞。

02不要把邮箱放进公共 URL优先使用不透明用户 ID；需要跨系统稳定时考虑服务端 HMAC。

03稳定性以主版本为边界生产系统应锁定包版本或 HTTP generation。
