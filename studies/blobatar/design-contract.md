# Blobatar 研究子项目设计契约

## 契约

| 字段 | 决定 |
| --- | --- |
| 进入模式 | Brief-led：将已确认的开源库研究结论落成可运行演示 |
| 请求版本 | R2，2026-08-20：收敛身份标识定位，增加社区 / 多 Agent Web 扩展 |
| 目标用户 | 评估开源项目复用价值的产品、前端、HCI 与多 Agent 研究人员 |
| 第一印象 | 先理解“它本质是头像，用作稳定视觉身份标识”，再看到社区与多 Agent 如何落地 |
| 视觉目标 | Editorial；研究展板式但保持工具可操作性 |
| 体验架构 | Editorial Flow：能力工作台 → 原理证据 → 场景 → 扩展路线 → 边界 |
| 视觉约束 | 头像是唯一高饱和视觉焦点；正文保持高对比；不伪造上游输出；支持 390px 手机 |
| 信息约束 | 一句话定义、身份表达公式、社区 / 多 Agent 主场景必须先于扩展路线；明确区分上游能力、研究演示和建议扩展 |
| 操作约束 | 纯静态前端、无后端、无密钥；保留原工作台，并增加社区 / 多 Agent 模式与 Agent 阶段切换 |
| 状态约束 | 默认、配置变化、表达变化、动画开关、社区模式、Agent 待命/分析/执行/复核/完成和 reduced-motion 均可理解 |
| 环境约束 | 可由 `python -m http.server` 运行；GitHub Pages 可直接部署；演示不依赖公共 Blobatar HTTP 服务 |
| 主流程 | 读懂身份标识定义 → 切换社区 / 多 Agent → 观察身份与状态 → 进入原能力工作台验证底层 → 阅读汇总和扩展方向 |
| 用户阶段 | 做好身份标识描述；汇总核心结论；Web 扩展社区 / 多 Agent；更新研究交付 |
| 必需产物 | R2 定义与汇总、双场景交互、更新后的研究 README、演示 README、浏览器验收和交接说明 |
| 自主授权 | 用户明确要求“获取该库并演示”，授权范围内的可逆实现和文档修改 |
| 用户决策边界 | 不发布远端、不创建外部服务、不把建议扩展表述为已实现 |

## 可观察完成标准

1. `vendor-projects/blobatar` 指向可追溯提交，并由 `upstream-lock.json` 记录。
2. 页面真实调用固定上游产物，而不是用手写近似图伪装 Blobatar。
3. 用户能完成 seed、外形参数、背景、表情、动画、批量身份五类交互。
4. 页面明确展示确定性、轻量、无状态、可访问配色、版本稳定性和隐私/碰撞边界。
5. 桌面、平板与 390px 手机无阻塞性裁切；键盘可达且焦点可见；reduced-motion 有降级。
6. 根 README、研究门户和 Pages 工作流都能找到并部署该子项目。
7. 首屏后明确展示“头像 = 视觉身份；表情 = 状态；文字 = 精确语义”的产品模型。
8. 社区模式能展示默认身份占位；多 Agent 模式能切换至少五个任务阶段并同步更新角色状态。

## 设计方向

| 决策 | 方向 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| 构图 | 顶部结论与大头像，下面是双栏工作台和研究章节 | 首屏不堆满卡片，输入与结果相邻 | 首次扫描能看懂输入、输出、非 AI 定位 |
| 字体 | 系统无衬线用于工具，衬线体用于研究标题 | 不下载字体；中文行长受控 | 离线可读，层级清晰 |
| 色彩 | 暖白纸面、深墨正文、酸绿研究标记；头像保持自身色彩 | UI 色不与头像争夺主焦点 | 控件、状态和正文保持清晰对比 |
| 材质 | 细线、编号、数据标签，少量圆角 | 不使用大面积玻璃拟态或重阴影 | 呈现研究仪器而非营销模板 |
| 动效 | 只保留上游头像动画与轻量状态过渡 | reduced-motion 时停用非必要动效 | 信息不依赖动画才能理解 |
