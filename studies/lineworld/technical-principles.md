# Lineworld 技术原理：程序化线稿角色、动物与世界

本文基于上游 `muratkamci/Lineworld` 固定提交 `2c0334295c2330e725087c0b21e19d7997a91e08`，以及衍生原型“线境：月夜追迹 v0.3.1”的源码与浏览器运行证据。目标是说明它真正实现了什么、哪些能力可以复用，以及哪些部分还不能视为正式游戏引擎。

## 1. 渲染链路

```text
键盘 / 鼠标 / AI状态
→ TypeScript在CPU上更新位置、关节角度、任务与缓冲数据
→ Three.js组织Scene、Camera、Geometry、Material和Group
→ WebGL提交顶点、线段、粒子与Shader绘制任务
→ GPU执行顶点/片元程序
→ 浏览器Canvas输出线稿世界
```

Three.js是场景和渲染抽象层，不是底层GPU接口。CPU负责输入、AI、动作状态、碰撞、任务图和每帧调度；GPU主要负责顶点变换、线段/粒子绘制、草地摆动、气味流动、距离衰减和最终像素输出。

## 2. 狗：代码生成的程序化四足角色

狗没有使用GLB、骨骼文件或烘焙动画，而是由代码生成：

1. `loftY()` / `loftZ()`定义一系列椭圆截面。
2. 相邻截面被连接为`BufferGeometry`三角面。
3. `WireframeGeometry`把表面转为线框。
4. `LineSegments`使用统一白色线材质绘制。
5. 身体、颈部、头部、两段尾巴、四条腿和灯笼分别挂在`THREE.Group`层级中。

腿部采用“大腿Group → 小腿Group → 脚掌Group”的父子变换结构，效果类似轻量骨骼，但没有`Skeleton`或蒙皮。

### 程序化动作

每帧根据时间、速度与动作权重计算姿势：

- `gait()`把步态划分为支撑期和摆动期。
- 行走与奔跑使用不同落脚相位和占空比。
- `sin()`、阻尼和插值产生身体起伏、俯仰、尾巴摆动与灯笼惯性。
- `runB`、`sniffB`、`digB`、`sit`、`tuck`等连续权重混合奔跑、嗅闻、挖掘、坐下和跳跃。
- 扑击锁定初始方向，组合向前速度、竖直速度与命中窗口。

这种路线的优势是资源极小、风格统一、参数可控；代价是新增攻击、受伤、转身、攀爬等复杂动作都需要继续编程。

## 3. 鸟、兔子和狐狸：动态线段缓冲

小动物使用预分配`Float32Array`和`BufferAttribute`：

1. 初始化固定容量的线段缓冲。
2. 每帧根据姿势重写线段端点。
3. 设置`needsUpdate = true`。
4. 使用`setDrawRange()`只绘制有效部分。

不同动物以小型状态机驱动：

| 动物 | 状态与运动 |
| --- | --- |
| 鸟 | 栖息、受惊、飞往另一落点；翅膀使用正弦摆动 |
| 环境兔 | 闲置、随机跳跃、受惊逃跑；跳跃使用半正弦高度曲线 |
| 狐狸 | 游荡、靠近后逃离；四足对角步态与尾巴摆动 |
| 目标白兔 | 平静、倾听、警觉、逃跑、闪避、入洞、被捕、等待、引路 |

环境动物主要提供氛围；目标白兔额外具有威胁评分、体力、碰撞、局部避障、洞穴意图和跨局关系角色。

## 4. 线稿世界为什么成立

视觉效果不是单一滤镜，而是统一渲染规则共同作用：

- 角色、树木、岩石和道具主要使用`LineSegments`。
- 黑色背景、白色线条和少量暖色/冷色状态色建立高对比。
- 雾与灯笼半径共同定义玩家的可见范围。
- 世界物体通过`geometry.setDrawRange()`实现逐笔显现。
- 草地以批量线段几何加顶点Shader摆动，避免逐根草对象。
- 气味使用Points、自定义属性和Shader脉冲形成动态导航轨迹。
- Web Audio实时合成环境声、吠叫与记忆反馈，不依赖音频样本。

因此真正可复用的是“程序化线段资产 + 显隐协议 + 感知范围 + 状态驱动反馈”，不是某一棵树或某一只兔子的造型。

## 5. 从视觉作品到游戏底座的验证

“线境：月夜追迹”增加了：

- 独立目标白兔与显式AI状态机。
- 狗的扑击动作、朝向/距离命中条件。
- 数据化平面关卡、圆形碰撞代理与导航锚点。
- 兔子逃生路线和放生引路路线验证。
- 捕获、放生、逃脱与localStorage关系存档。
- `prey → guide`跨局身份变化。
- 稳定ID中文任务图、中文HUD、首次教学与阶段目标。

这证明Lineworld可以承载“输入 → 感知 → AI → 动作 → 结果 → 存档 → 下一局内容”的闭环，但仍不等于通用引擎。

## 6. 正式游戏需要补齐什么

### 动物与角色

- 将程序化角色抽象成可配置`AnimalDefinition`、Rig、感知、移动与动作控制器。
- 增加动画优先级、打断、冷却、受伤、死亡和脚底接触处理。
- 内容量较大时采用混合资产管线：重要角色使用glTF骨骼资产，小型氛围动物保留程序化线段。
- 使用自定义线框Shader维持骨骼角色的线稿风格。

### 世界与性能

- 把程序化Chunk状态、任务实体和收集结果持久化。
- 建立对象池、LOD、Worker生成、草密度与视距质量档位。
- 迁移已弃用的`THREE.Clock`，拆分当前约170 kB gzip的入口包。
- 建立桌面、集显与移动GPU性能矩阵。

### UI

Three.js Canvas继续负责空间世界；DOM负责文字、HUD、菜单与无障碍。正式游戏应从“控制器直接修改DOM”升级为：

```text
Three.js游戏核心
→ 发布只读快照和领域事件
→ UI状态仓库
→ HUD / 对话 / 任务 / 背包 / 暂停 / 设置组件
```

UI优化重点不是装饰，而是信息层级、情境操作、键鼠/手柄/触屏适配、暂停设置、存档反馈、字幕、焦点管理和响应式布局。

## 7. 阶段判断

现阶段研究已经足以支持技术选型：

- 适合：风格化线稿游戏、程序化角色原型、感知型探索、轻量动物AI和空间叙事。
- 需要工程化后再用：正式任务系统、复杂战斗、大规模生态和移动端产品。
- 不适合直接替代：写实角色资产管线、成熟物理引擎、通用开放世界框架或完整商业游戏引擎。

后续只有出现真实的多动物任务、移动端发行或内容生产需求时，才需要继续扩展专项研究。
