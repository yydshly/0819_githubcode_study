# Punk Skill 能力实验室 · 设计契约

## 项目契约

| 字段 | 决定 |
| --- | --- |
| Entry mode | Brief-led implementation |
| Request revision | 5 |
| Target user and context | 研究者、内容创作者与 Agent 工程师；需要快速判断 Punk-Skill 的真实能力、使用方式与扩展价值 |
| Desired first impression | 一眼知道最终交付不是单张图，而是一套包含平台文案、准确封面、Alt Text、标签和生成记录的发布素材包 |
| Visual ambition | Editorial |
| Experience architecture | Hybrid Workspace：左侧场景输入与控制，右侧实时展示编译结果；下方为证据、上游样例与扩展实验 |
| Visual constraints | 独立的研究实验室视觉；不复制上游页面；深浅主题均可读；图片是增强层，不承载唯一信息 |
| Information constraints | 明确区分上游事实、研究实现、预生成研究样例和规划能力；上游许可证未明确，示例图不复制进仓库 |
| Operation constraints | 零依赖静态 HTML/CSS/JS；无需登录、后端或密钥；可由 `python -m http.server` 运行 |
| State constraints | 场景切换、风格切换、基础/扩展对照、提示词预览、复制反馈、主题切换均有明确状态 |
| Environment constraints | GitHub Pages 与本地静态服务器；桌面、平板、390px 手机；键盘可达；支持 reduced-motion |
| Primary journey | 安装上游与研究扩展 → 选择一个真实发布场景或粘贴内容 → 编辑发布包 → 运行质量检查 → 导出含真实 PNG、文案、Prompt 与 manifest 的 ZIP → 在文件层复核后再人工发布 |
| User-defined phases | 修复 `$punk-publish` 安装发现；实现真实 PNG/ZIP 导出；增加质量检查；补产品、研究、活动、课程完整发布场景；建立研究评测协议；保留上游图片能力作为视觉子步骤 |
| Required artifacts | 双依赖安装指令；可校验的 `punk-publish` Skill；浏览器 ZIP/PNG 导出器；真实下载包；质量检查面板；五套完整发布预设；研究评测协议；浏览器下载物、响应式与交接证据 |
| Autonomy authorization | 用户已明确要求获取、构造、扩展并展示；允许在现有研究主库中直接实现可逆的本地文件变更 |
| User-decision boundary | 不安装到全局 Skills；不发布或推送；不连接小红书账号或真实发布 API；不调用真实外部生成 API；不复制许可证不明确的上游源码和图片进受版本控制目录 |

## 可观察完成标准

1. 本地研究检出能够固定到明确提交号，两个上游校验脚本可以执行。
2. 页面首屏明确展示 Punk-Skill 的四段式能力链路和“非模型”边界。
3. 八个使用场景可以切换，并同步呈现任务、适配理由、结构化内容理解、风格选择与提示词摘要。
4. 至少一个扩展场景能在页面中与基础能力进行可见对照。
5. 上游 24 个封面风格与 5 个头像风格全部通过来源链接展示；每张图下方都有风格名、风格描述、适用场景和视觉关键词，不将图片复制进本仓库。
6. 桌面、平板与 390px 手机无关键内容裁切；深浅主题、键盘、复制反馈和 reduced-motion 有验证记录。
7. 页面首个正文区提供一个可操作的真实使用台：封面 / 头像切换、素材输入、渠道和风格选择、生成 / 仅 Prompt 模式、可复制指令，以及明确的真实运行位置和产物路径。
8. 页面展示“用户输入 → Skill 确认 → Prompt 文件 → 图像 Provider → 可发布图片”的完整现实对话，不把网页模拟器误写成已执行 Agent。
9. 仓库内存在通过 `quick_validate.py` 的 `punk-publish` 研究 Skill；其说明明确依赖 `punk-cover`、默认不自动发布，并定义完整发布包结构。
10. 页面默认输出模式为“小红书完整发布包”，同时可见标题、正文、摘要、CTA、标签、Alt Text、无字底图、可靠文字封面、Prompt 路径和 manifest。
11. 发布包文案字段随源内容编辑而更新；用户可以分别复制正文、Alt Text、调用指令和 manifest；页面明确标注预览是确定性研究模拟。
12. 页面分别提供上游视觉 Skills 与本地 `$punk-publish` 研究扩展的发现指令；默认调用不会再隐含一个未安装的 Skill。
13. 用户可在浏览器导出真实 ZIP；ZIP 至少包含可打开的 `visual/cover.png`、原始研究底图、6 个文案文件、Prompt、`cover-copy.json` 与记录实际字节哈希的 manifest。
14. 页面提供可观察的发布前质量检查，覆盖标题长度、正文、标签、Alt 与标题一致性、比例和草稿状态；失败项不会被展示为通过。
15. 除 AI Agent 默认场景外，至少提供产品发布、研究解读、活动宣传和课程知识四套完整文案与视觉预设。
16. 研究文档给出单图与完整发布包的对照评测协议、指标、样本单位和停止边界，不虚构尚未运行的人体实验结果。

## 设计方向

| 决策 | 方向 | 对研究目标的作用 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- | --- |
| 信息层级 | “真实怎么用 → 原理 → 场景地图 → 场景演示 → 完整原生图库 → 扩展” | 先消除操作不确定性，再解释架构与研究价值 | Hero 主按钮进入真实使用台；使用台必须在原理之前 | 首次扫描可回答“发给谁、发什么、得到什么” |
| 真实使用台 | 左侧构造现实任务，右侧持续显示可复制调用指令与预期产物 | 让抽象 Skill 变成可以离开网页执行的下一步 | 网页明确只生成调用指令，不伪装成真实 Agent 或图像 Provider | cover / avatar 和 generate / prompt-only 四种组合都能生成正确指令 |
| 发布包工作台 | 文案编辑区、封面预览区与文件清单形成同一操作面 | 让用户看到图片只是发布包中的一个资产 | 默认选中完整发布包；视觉子任务仍可单独切换查看 | 首次操作能指出“发布正文在哪里、封面在哪里、如何复用和追踪” |
| 工作台 | 场景适配、内容理解和编译结果并列 | 让抽象 Skill 规则变成可操作过程 | 场景切换必须同步更新使用目标、适配理由、输入理解、图片和 Prompt | 八个场景切换无刷新完成 |
| 视觉语言 | 墨黑/纸白底，酸性绿与橙红作为研究标记 | 与现有 Outfit Director 区分，同时保持研究主库气质 | 颜色不作为唯一状态编码 | 深浅主题中标签和按钮仍可辨识 |
| 扩展表达 | 同一场景的 baseline / brand-system 对照 | 直接展示扩展带来的结构变化 | 对照内容和样例必须成对出现 | 用户能指出扩展增加了哪些约束 |
| 图片策略 | 自有预生成研究样例 + 上游远程链接 | 避免许可证风险并保留视觉证据 | 每张图标明来源和生成边界 | 不把上游图片提交到本仓库 |
| 图库策略 | 29 项数据驱动渲染 + 分类筛选 + 搜索 | 在完整覆盖下仍保持可浏览性 | “全部”计数为 29；“封面”为 24；“头像”为 5；关键词可缩小结果 | 图片下方信息不依赖悬停，手机端仍完整可读 |
